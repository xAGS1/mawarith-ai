# LLM-first RAG refactor

The default production path is now one strict Qwen understanding call followed by either multi-source educational RAG or deterministic calculation. The existing public response schema is preserved. The frontend, executable rule catalog, Quran adapter, Qdrant collection and model configuration were not changed.

## Before and after

Previously, API mode and deterministic phrase/concept routing selected an educational path; direct-definition quality gates, curated answers and exact-text claim matching could reject natural questions or useful paraphrases. Case allocations were generated by Qwen and then checked for arithmetic consistency.

Now: question → Qwen structured understanding → approved-source semantic retrieval → Qwen explanation → supplied-citation and clear-error checks. For calculations: Qwen extracts strict heir/count records → existing readiness and coverage checks → deterministic allocation from existing rule results → exact fraction verification → Qwen explanation of the immutable result. Solver distributions are never replaced by generated prose.

The normal semantic path bypasses deterministic request phrases, curated concept-answer branches, direct-definition-only gates and the exact-text educational claim matcher. Legacy educational helpers remain available for compatibility during understanding-service failure. API mode is used only in this service-failure fallback: live testing showed supplying the frontend's legacy learn hint to the semantic model incorrectly biased concrete cases into educational answers.

## Understanding schema

```json
{
  "intent": "educational | calculation | clarification_needed | out_of_scope",
  "language": "ar | en",
  "topic": "string",
  "retrieval_query": "string",
  "concepts": ["string"],
  "case": {
    "heirs": [{"relation": "canonical Arabic relationship", "count": 1}],
    "relationships": ["canonical Arabic relationship"],
    "counts": {"canonical Arabic relationship": 1}
  },
  "clarification_question": null
}
```

`case` may be null. Fields forbid extras and bound lengths/counts. Counts are derived from strict extracted heir records, never guessed. Harmless definite-article normalization preserves relationship chains and sibling qualifiers. No shares or rulings are accepted in understanding output.

## Retrieval and safety

UQU PDF windows use the existing BGE-M3 model and a small in-memory vector cache. Kuwaiti candidates use the existing Qdrant collection, restricted by general inheritance article metadata, without concept-specific query expansion. Oversized retrieved chunks are searched as overlapping exact windows. Approved locally cached Quran verses are validated through the existing exact-text adapter. The same source/text record interface supports adding another approved provider.

Educational-reference priority is a small ranking preference, not a definition sufficiency gate. Original question, generated retrieval query and requested concepts all remain in the embedding query. No corpus re-ingestion or Qdrant replacement was performed.

Educational paraphrases need valid supplied citations, either inline or in the strict declared-ID field. Clear unsupported numeric shares and heir entitlements are removed sentence by sentence. Narrower-versus-broader scope checks remain. The lightweight filter is not a general semantic proof: unsupported conditions or meaning changes can still escape lexical checks. Model outputs still require evaluation; this change does not establish comprehensive religious correctness.

Exact excerpts remain separate, unchanged. Internal source hashes/offsets, candidate data and evidence IDs are retained in debug traces and removed from public responses. The public schema still uses mode, answer, decision_state, sources, source_excerpts and case_details; the verified distribution lives in case_details.result.

## Remaining calculation limits

Only existing executable fixed-share and single weighted-residue rules are allocated. Missing coverage, overlapping allocations, unsupported remainder, awl/radd and advanced cases remain referrals under current readiness/coverage protection. In particular, no executable son-only rule exists, so recognizing `مات وترك ابنان فقط` does not make that case solvable. Generic child wording can require further relationship detail or fall outside current rule coverage. No new religious ruling was added to expand this coverage.
